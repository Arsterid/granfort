# GRANFORT

**GRANFORT** — веб-платформа для представления продукции бренда и управления каталогом автомобильных решений.

Проект объединяет публичный сайт, административную панель, каталог автомобилей и API. Администратор управляет товарами, изображениями и их совместимостью с конкретными модификациями автомобилей. На публичной странице показываются только опубликованные товары.

## Возможности

### Публичный сайт

- Главная страница GRANFORT с информационными секциями и контактами.
- Вывод опубликованных товаров из базы данных.
- Отображение изображений и совместимости товара с автомобилями.
- Получение публичного каталога через API.

### Административная панель

- Обзор состояния товарного и автомобильного каталогов.
- Создание, редактирование и удаление товаров.
- Управление статусами товаров: черновик, опубликован и архив.
- Загрузка и удаление изображений товаров.
- Управление марками, моделями и модификациями автомобилей.
- Привязка товара к нескольким модификациям автомобилей.
- Контроль незаполненных товарных карточек и просмотр последних изменений.

Для публикации товара требуется указать хотя бы одну совместимую модификацию автомобиля. Это правило проверяется на сервере.

### Каталог автомобилей

Каталог имеет иерархическую структуру:

```text
Марка
└── Модель
    └── Модификация
        ├── Поколение
        ├── Годы выпуска
        └── Комплектация
```

Товар связывается с конкретными модификациями, а не только с маркой или моделью. Это позволяет точнее описывать применимость продукции.

## Быстрый запуск на сервере

Для развёртывания используется Docker Compose. Next.js, PostgreSQL и Caddy работают в отдельных контейнерах. Наружу публикуются только порты Caddy; приложение и база данных доступны во внутренней сети Docker.

### Требования

- Linux-сервер или VPS.
- Установленные Docker Engine и Docker Compose v2 plugin.
- Git, Bash, `curl`, `openssl` и `getent` на сервере.
- Домен или поддомен, направленный на публичный IP сервера.
- Доступность входящих TCP-портов `80` и `443`. UDP-порт `443` используется для HTTP/3.
- Свободные порты `80` и `443`.

Перед запуском настройте DNS-запись `A` для выбранного домена. Если используете `AAAA`, она также должна указывать на доступный IPv6-адрес этого сервера. Неверная или устаревшая IPv6-запись может помешать выпуску сертификата.

### Установка

Клонируйте репозиторий и перейдите в каталог проекта:

```bash
git clone <repository-url> granfort
cd granfort
chmod +x ./start.sh
```

Запустите установщик:

```bash
./start.sh
```

При первой установке скрипт:

1. Проверит Docker, Compose и необходимые системные утилиты.
2. Запросит домен сайта, email для ACME-сертификата и email администратора.
3. Создаст `.env` и сгенерирует секреты для PostgreSQL, Auth.js и первоначального пароля администратора.
4. Соберёт Docker-образы.
5. Запустит PostgreSQL и дождётся готовности базы.
6. Применит Prisma migrations.
7. Запустит Next.js и Caddy.
8. Выполнит начальное заполнение: создаст администратора, а также базовые марки JAC и HAVAL с моделями T9 и H3.
9. Проверит доступность сайта по HTTPS.

После успешной установки скрипт выведет адрес сайта и первоначальные учётные данные администратора. **Сохраните сгенерированный пароль:** при повторном запуске он не будет показан снова.

Административная панель доступна по адресу:

```text
https://<ваш-домен>/admin
```

Caddy автоматически получает и продлевает TLS-сертификат. Отдельно запускать Certbot или вручную выпускать сертификат не требуется.

### Обновление приложения

После получения изменений из Git выполните:

```bash
git pull
./start.sh
```

Установщик использует существующий `.env`, пересобирает образы и запускает миграции перед приложением. База данных, загруженные изображения и данные Caddy хранятся в отдельных именованных Docker volumes.

Повторное начальное заполнение пропускается с помощью локального маркера `.granfort-seeded`. Сам seed также рассчитан на повторный запуск: существующий пользователь не перезаписывается, базовые марки и модели создаются через `upsert`.

### Настройки окружения

Рабочий `.env` создаётся установщиком. Шаблон переменных находится в `.env.example`.

Основные параметры:

| Переменная | Назначение |
|---|---|
| `DOMAIN` | Домен сайта, используемый Caddy |
| `ACME_EMAIL` | Email для ACME и уведомлений центра сертификации |
| `POSTGRES_USER` | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |
| `POSTGRES_DB` | Имя базы данных |
| `DATABASE_URL` | Строка подключения приложения и Prisma к PostgreSQL |
| `AUTH_SECRET` | Секрет Auth.js |
| `AUTH_TRUST_HOST` | Доверие заголовкам reverse proxy в серверном окружении |
| `ADMIN_EMAIL` | Email первоначального администратора |
| `ADMIN_PASSWORD` | Пароль первоначального администратора |
| `ADMIN_NAME` | Имя первоначального администратора |
| `UPLOAD_DIR` | Каталог хранения загруженных изображений внутри контейнера |

`.env` содержит секреты и не должен попадать в Git или передаваться посторонним. В репозитории хранится только `.env.example`.

Если администратор с указанным email уже существует, seed пропустит его. Изменение `ADMIN_PASSWORD` в `.env` само по себе не меняет хеш пароля существующего пользователя.

## Локальная разработка

Для разработки предусмотрен отдельный Dev Container. Его Compose-файл находится в `.devcontainer/` и не пересекается с основным `compose.yaml`, предназначенным для запуска приложения.

### Запуск Dev Container

1. Установите Docker и Visual Studio Code.
2. Установите расширение **Dev Containers**.
3. Откройте репозиторий в VS Code.
4. Выполните команду **Dev Containers: Reopen in Container**.
5. Дождитесь запуска контейнеров `app` и `db`.

Dev Container предоставляет Node.js 24 и PostgreSQL. Каталоги `node_modules`, `.next`, база данных и загруженные файлы размещаются в соответствующих Docker volumes.

### Переменные для разработки

В корне репозитория создайте `.env` для локальной разработки. Dev Container уже передаёт `DATABASE_URL` и `UPLOAD_DIR`; следующие значения можно добавить в `.env` для seed и Auth.js:

```dotenv
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=change-this-local-password
ADMIN_NAME=GRANFORT Developer
AUTH_SECRET=replace-with-a-local-secret
AUTH_TRUST_HOST=true
```

Для локальной базы Dev Container использует подключение:

```text
postgresql://granfort:granfort_local@db:5432/granfort?schema=public
```

### Установка зависимостей и запуск

В терминале Dev Container:

```bash
npm ci
npx prisma generate
npx prisma migrate dev
npx prisma db seed
npm run dev
```

Приложение будет доступно по адресу, который выводит Next.js, обычно `http://localhost:3000`.

Seed можно повторять: существующий администратор не изменяется, базовые марки и модели обновляются через `upsert` без перезаписи существующих полей.

## Работа с каталогом

### Товары

В разделе `/admin/products` администратор может создавать и редактировать товарные карточки, задавать название, URL-адрес, артикул, описание и порядок сортировки, управлять изображениями и статусом.

Доступные статусы:

- **Черновик (`DRAFT`)** — товар ещё не опубликован.
- **Опубликован (`PUBLISHED`)** — товар доступен на публичном сайте и в публичном API.
- **Архив (`ARCHIVED`)** — товар хранится в базе, но не отображается в публичном каталоге.

Для публикации товар должен иметь хотя бы одну связь с модификацией автомобиля.

### Автомобильный каталог

В административной панели доступны разделы:

- `/admin/vehicles/brands` — марки;
- `/admin/vehicles/models` — модели;
- `/admin/vehicles/variants` — модификации.

Сначала создаётся марка, затем модель этой марки, после чего для модели добавляются конкретные модификации с поколением, годами выпуска и комплектацией.

### Совместимость товара

В форме товара найдите нужную модификацию через поиск и выберите её. Добавленные модификации отображаются отдельным списком; ненужную связь можно удалить. У одного товара может быть несколько совместимых модификаций.

### Изображения

Изображения загружаются через административную панель и хранятся в файловом каталоге `UPLOAD_DIR`. В Docker-развёртывании он подключён к постоянному volume `uploads-data`, поэтому пересоздание контейнера приложения не удаляет загруженные файлы.

## API и OpenAPI

HTTP API использует версионированный префикс `/api/v1`.

Основные публичные и административные маршруты:

| Маршрут | Назначение |
|---|---|
| `GET /api/v1/products` | Опубликованные товары для публичного каталога |
| `/api/v1/products` | Создание и работа с товарами |
| `/api/v1/admin/products` | Административный список товаров |
| `GET /api/v1/admin/overview` | Агрегированная статистика административной панели |
| `/api/v1/vehicle-brands` | Марки автомобилей |
| `/api/v1/vehicle-models` | Модели автомобилей |
| `/api/v1/vehicle-variants` | Модификации автомобилей |

Изменяющие операции и административные ресурсы защищены серверной проверкой прав администратора. Валидация входных данных выполняется с помощью Zod.

OpenAPI-контракт находится в `openapi/registry.ts` и формируется из Zod-схем. Скрипт `npm run swagger` запускает Next.js в режиме Webpack, используемом проектом для Swagger UI.

## Хранение данных

Docker Compose использует именованные volumes:

| Volume | Содержимое |
|---|---|
| `postgres-data` | Файлы базы PostgreSQL |
| `uploads-data` | Загруженные изображения товаров |
| `caddy-data` | Сертификаты, приватные ключи и состояние ACME Caddy |
| `caddy-config` | Состояние конфигурации Caddy |

Команда `docker compose down` удаляет контейнеры и сеть, но сохраняет именованные volumes.

**Не запускайте `docker compose down -v`, если хотите сохранить базу, изображения и сертификаты.** Флаг `-v` удаляет именованные volumes. Для важных данных также рекомендуется делать резервные копии базы и каталога загруженных файлов: Docker volumes не защищают от потери самого диска или VPS.

## Устранение неполадок

### Сайт не открывается по HTTPS

Проверьте:

1. DNS-записи домена указывают на IP-адрес сервера.
2. Входящие порты TCP `80` и `443` разрешены в firewall и у хостинг-провайдера.
3. На сервере нет другого процесса, занимающего эти порты.
4. Контейнеры запущены: `docker compose ps`.
5. Логи Caddy: `docker compose logs -f caddy`.

Caddy не сможет получить публичный сертификат, пока домен не доступен для ACME-проверки.

### Приложение не запускается

Посмотрите логи:

```bash
docker compose logs --tail=100 app migrate db
```

Если миграции завершились с ошибкой, приложение не запустится. Сначала устраните причину ошибки миграции и повторно выполните `./start.sh`.

### Не загружаются изображения

Проверьте, что контейнер приложения запущен и volume `uploads-data` подключён к `/var/lib/granfort/uploads`. Также проверьте логи приложения и доступное место на диске VPS.

### Нужно изменить пароль администратора

Изменение `ADMIN_PASSWORD` в `.env` не меняет пароль уже созданного пользователя: seed пропускает существующий email. Для смены пароля используйте предусмотренный приложением механизм управления учётной записью либо отдельную административную процедуру. Не удаляйте пользователя и не очищайте базу ради повторного запуска seed.
